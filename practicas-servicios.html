Azure Blob Storage y enlaces SAS

Guarda archivos privados y aprende a compartir uno durante un tiempo limitado.

DIFICULTADBásica
TIEMPO45–60 minutos
COSTOMuy bajo
GRUPOrg-lab-storage

Piensa en un casillero

La cuenta de almacenamiento es el edificio; el contenedor es un casillero y cada blob es un archivo guardado. Si el casillero es privado, nadie puede abrirlo sin una llave autorizada.

¿Qué problema resuelve?

Permite guardar imágenes, PDF, videos, respaldos y otros archivos sin depender del disco de una máquina virtual. Los archivos permanecen aunque la VM esté apagada.

  3. Guárdalo como evidencia-storage.txt. No incluyas contraseñas, documentos de identidad ni información personal sensible.

FASE C · CREAR EL CONTENEDOR PRIVADO

Encuentra “Contenedores” aunque cambie el portal

  1. Dentro de la cuenta de almacenamiento, abre el menú izquierdo.
  2. Despliega Almacenamiento de datos y selecciona Contenedores.
  3. Si no aparece, usa Buscar en el menú y escribe “contenedores”. Otra ruta posible es Información general → Blobs.
  4. Selecciona + Contenedor.
  5. Nombre: materiales. En Nivel de acceso anónimo, conserva Privado (sin acceso anónimo).
  6. Selecciona Crear y luego abre el contenedor.
  7. Selecciona Cargar, elige evidencia-storage.txt y confirma la carga.
⚠

Si solo ves “Recursos compartidos de archivos”

Comprueba en Información general que el tipo de cuenta sea StorageV2 (uso general v2). Una cuenta especializada FileStorage no muestra contenedores de blobs.

FASE D · COMPROBAR PRIVACIDAD Y CREAR LA SAS

Prueba primero el bloqueo y después la llave temporal

  1. Abre el blob evidencia-storage.txt y copia su URL.
  2. Pega la URL en una ventana privada del navegador. El archivo no debe abrir; puede aparecer un mensaje XML de autorización o recurso no encontrado.
  3. Regresa al blob y selecciona Generar SAS. También puede aparecer en el menú de tres puntos.
  4. En Método de firma, usa Clave de cuenta para esta práctica. En un sistema real se prefiere delegar con Microsoft Entra cuando sea posible.
  5. Marca únicamente el permiso Leer.
  6. Establece una expiración de 15 minutos y deja HTTPS solamente como protocolo permitido.
  7. Selecciona Generar token SAS y dirección URL.
  8. Copia la URL de SAS de blob completa y ábrela en la ventana privada. Ahora el contenido debe aparecer.
🔐

La URL SAS es una credencial

No la publiques en una captura, correo abierto o repositorio. Cualquier persona que tenga el vínculo podrá usar sus permisos hasta que venza o deje de existir el archivo.

Resultado esperado

La URL normal falla porque el contenedor es privado. La URL que incluye el token SAS abre el archivo durante el tiempo autorizado.

Azure Static Web Apps

Publica la misma clase de sitio HTML sin administrar una máquina virtual.

DIFICULTADBásica
TIEMPO60–75 minutos
COSTOPlan Gratis
GRUPOrg-lab-static

Piensa en una imprenta automática

Guardas el original en GitHub. Cada vez que actualizas el repositorio, una acción toma los archivos y publica una nueva versión del sitio.

¿Qué cambia frente a NGINX?

Con NGINX administras Ubuntu, puertos, actualizaciones y archivos. Static Web Apps administra la publicación y entrega una dirección HTTPS. Tú te concentras en HTML, CSS y JavaScript.

FASE A · PREPARAR GITHUB

Crea un repositorio con un sitio sencillo

  1. Entra en GitHub con tu cuenta y selecciona New repository.
  2. Nombre: sitio-estatico-azure. Para esta práctica puedes elegir Public.
  3. Marca Add a README file y selecciona Create repository.
  4. Selecciona Add file → Upload files.
  5. Carga el index.html, las hojas CSS, scripts e imágenes de tu sitio. El archivo index.html debe quedar en la raíz del repositorio.
  6. Escribe un mensaje como “Primera versión del sitio” y selecciona Commit changes.
⚠

Nunca subas secretos a GitHub

No cargues claves .pem, contraseñas, tokens SAS, cadenas de conexión ni archivos con datos personales.

FASE D · ACTUALIZACIÓN AUTOMÁTICA

Comprueba la integración continua

  1. En GitHub abre index.html y selecciona el lápiz Edit this file.
  2. Cambia un título o agrega un párrafo que diga “Versión 2 publicada automáticamente”.
  3. Selecciona Commit changes y confirma el cambio en la rama main.
  4. Abre nuevamente Actions y observa una nueva ejecución.
  5. Cuando termine, actualiza la dirección de Static Web Apps con Ctrl + F5.
✓

Esto es CI/CD

El cambio guardado en GitHub activa automáticamente la construcción y publicación del sitio. No tuviste que copiar los archivos manualmente a un servidor.

La acción de GitHub falla o muestra que no encuentra index.html
  • Confirma que index.html esté en la raíz del repositorio.
  • En el archivo de flujo ubicado en .github/workflows, revisa que app_location apunte a /.
  • Para HTML sin compilación, la ubicación de salida es /. Si el portal generó otro valor, corrígelo con cuidado y vuelve a ejecutar el flujo.
  • No borres el secreto que Azure agregó al repositorio.
El sitio abre, pero faltan estilos o imágenes

Revisa las mayúsculas y minúsculas. En Internet, Imagenes/logo.png y imagenes/logo.png pueden considerarse rutas diferentes. Usa rutas relativas como css/estilos.css, no rutas de Windows como C:\Mis archivos\....

Evidencias de la práctica

Limpieza

  1. Elimina rg-lab-static desde Azure.
  2. En GitHub elimina el archivo de flujo azure-static-web-apps-....yml de .github/workflows si conservarás y modificarás el repositorio. Así evitas ejecuciones fallidas después de borrar el recurso.
  3. Puedes conservar el repositorio como evidencia; no genera costo de Azure.

FASE C · CREAR TABLAS Y DATOS

Usa el Editor de consultas del portal

  1. Cuando finalice la implementación, selecciona Ir al recurso.
  2. En el menú de la base de datos, selecciona Editor de consultas (versión preliminar).
  3. Elige Autenticación SQL e inicia sesión con sqladminlab y la contraseña creada.
  4. Si aparece “La dirección IP no está permitida”, selecciona el vínculo Agregar IP a la lista de permitidas, espera hasta cinco minutos y vuelve a conectar.
  5. Copia y ejecuta el primer bloque. La palabra GO separa grupos de instrucciones.
CREAR LA TABLA
CREATE TABLE Aprendices (
    Id INT IDENTITY(1,1) PRIMARY KEY,
    Nombre NVARCHAR(100) NOT NULL,
    Programa NVARCHAR(120) NOT NULL,
    Correo NVARCHAR(150) NULL,
    FechaRegistro DATETIME2 NOT NULL DEFAULT SYSDATETIME()
);
GO
INSERTAR Y CONSULTAR
INSERT INTO Aprendices (Nombre, Programa, Correo)
VALUES
('Laura Gomez', 'Redes de datos', 'laura@ejemplo.com'),
('Carlos Perez', 'Desarrollo de software', 'carlos@ejemplo.com'),
('Ana Ruiz', 'Redes de datos', NULL);
GO

SELECT Id, Nombre, Programa, Correo, FechaRegistro
FROM Aprendices
ORDER BY Id;
GO
Resultado esperado

La cuadrícula debe mostrar tres filas. Los valores de Id aparecen automáticamente y FechaRegistro contiene la fecha del servidor.

FASE D · PRACTICAR CRUD

Crea, lee, actualiza y elimina

CRUD resume las cuatro operaciones más comunes: crear, leer, actualizar y eliminar datos.

ACTUALIZAR Y VERIFICAR
UPDATE Aprendices
SET Programa = 'Administracion de redes'
WHERE Nombre = 'Laura Gomez';

SELECT * FROM Aprendices
WHERE Nombre = 'Laura Gomez';
GO
ELIMINAR Y CONTAR
DELETE FROM Aprendices
WHERE Nombre = 'Carlos Perez';

SELECT COUNT(*) AS TotalAprendices
FROM Aprendices;
GO
Resultado esperado

Laura aparece con el nuevo programa y el conteo final devuelve 2. La eliminación usa una condición WHERE; sin ella se borrarían todas las filas.

!

Lee antes de ejecutar DELETE

Primero ejecuta un SELECT con la misma condición para confirmar qué filas serán afectadas. En esta práctica los nombres son ficticios.

No puedo iniciar sesión en el Editor de consultas
  • Comprueba que seleccionaste Autenticación SQL y no Microsoft Entra.
  • Usa el administrador del servidor lógico, no el correo de Azure.
  • Agrega la IP actual desde el mensaje del editor o desde Servidor SQL → Redes → Reglas de firewall.
  • El editor utiliza HTTPS por el puerto 443; algunas redes institucionales con proxy pueden bloquearlo.
  • Si la base estaba pausada, espera unos minutos mientras se reactiva.
La tabla ya existe al repetir el ejercicio

No ejecutes nuevamente CREATE TABLE. Puedes continuar con las consultas o eliminar solamente la tabla de práctica con DROP TABLE Aprendices; y comenzar de nuevo. Esta instrucción elimina la tabla y sus datos.

Evidencias de la práctica

Limpieza

  1. Guarda una captura de la cuadrícula ocultando el servidor y las credenciales.
  2. Cierra el Editor de consultas para no mantener conexiones que impidan la pausa automática.
  3. Elimina rg-lab-sql y confirma que desaparezcan la base y el servidor lógico.

Piensa en las llaves de un edificio

Una llave puede abrir la recepción sin abrir las oficinas. El rol Lector permite mirar recursos, pero no crearlos, modificarlos ni eliminarlos.

Identidad, rol y ámbito

FASE A · PREPARAR EL RECURSO Y LA PAREJA

Define claramente qué se compartirá

  1. Trabaja con un compañero y definan quién será Aprendiz A, propietario de los recursos, y quién será Aprendiz B, lector.
  2. El Aprendiz A abre un grupo existente que todavía contenga un recurso de práctica, por ejemplo rg-lab-storage. No uses un grupo con datos personales.
  3. En el grupo abre Control de acceso (IAM) → Ver mi acceso.
  4. Comprueba que tu cuenta tenga permiso para asignar roles, normalmente Propietario o Administrador de acceso de usuario.
  5. El Aprendiz B entrega el correo exacto de su cuenta institucional. Nunca entrega su contraseña.

  1. En Control de acceso (IAM), abre Asignaciones de roles.
  2. Selecciona Agregar → Agregar asignación de roles.
  3. En la pestaña Rol, busca y selecciona Lector.
  4. Selecciona Siguiente.
  5. En Asignar acceso a, elige Usuario, grupo o entidad de servicio.
  6. Selecciona + Seleccionar miembros, busca el correo del Aprendiz B y selecciónalo.
  7. Selecciona Revisar y asignar dos veces.
  8. Regresa a Asignaciones de roles y filtra por Lector para comprobar el nombre y el ámbito.
Resultado esperado

Existe una asignación que une al Aprendiz B con el rol Lector en el grupo elegido, no en toda la suscripción.

FASE C · VERIFICAR LO PERMITIDO Y LO NEGADO

Prueba con la cuenta del Aprendiz B

  1. El Aprendiz B abre una ventana privada e inicia sesión con su propia cuenta.
  2. Si tiene varios directorios, abre Directorios y suscripciones y cambia al directorio donde recibió el acceso.
  3. Busca Grupos de recursos y abre el grupo compartido. La propagación puede tardar algunos minutos.
  4. Abre los recursos y comprueba que puede ver su información general.
  5. Intenta iniciar una acción de cambio segura, por ejemplo abrir Etiquetas → Editar. No confirmes si el botón aparece.
  6. Azure debe negar la modificación o deshabilitar el control porque Lector no incluye acciones de escritura.
  7. El Aprendiz B cierra sesión. No guarden credenciales en el navegador compartido.
✓

Que una acción sea rechazada es un resultado correcto

La práctica demuestra que autenticarse y ver un recurso no significa tener permiso para modificarlo.

FASE D · COMPARAR LOS ROLES

Explica cuál corresponde a cada trabajo

RolQué permite
LectorVer recursos y configuraciones, sin modificarlos.
ColaboradorCrear y administrar recursos, pero normalmente no entregar acceso a otros.
PropietarioAdministrar recursos y también conceder acceso. Debe usarse con mucho cuidado.

Escribe una situación para cada rol. Ejemplo: un auditor recibe Lector; un técnico que administra recursos puede recibir Colaborador; el responsable de acceso puede requerir Propietario o un rol más específico.

No encuentro al compañero por su correo

Probablemente no pertenece al mismo directorio. Un administrador puede invitarlo como usuario externo desde Microsoft Entra ID, pero algunas instituciones no lo permiten. No cambies de suscripción ni crees usuarios sin autorización; realiza la actividad como demostración guiada.

“Agregar asignación de roles” está deshabilitado

Tu cuenta puede administrar recursos sin tener permiso para entregar acceso. Abre Ver mi acceso. Necesitas una función que incluya Microsoft.Authorization/roleAssignments/write, como Propietario o Administrador de acceso de usuario.

Evidencias de la práctica

Retirar el acceso

  1. El Aprendiz A regresa a Control de acceso (IAM) → Asignaciones de roles.
  2. Busca la asignación del Aprendiz B, selecciónala y pulsa Quitar.
  3. Confirma conscientemente la eliminación del permiso.
  4. Elimina el grupo de recursos cuando ya no se use en otras prácticas.
